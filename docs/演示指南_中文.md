# Rental Radar — 中文上台指南与逐页讲稿

## 开始演示

用 Chrome 或 Edge 打开 `Rental_Radar_Stage_Ready.html`。离线示例和内嵌模型实验不需要安装软件。正式上台优先使用离线示例，实时查询留作问答。

- 方向键／空格：翻页；F：全屏；O：总览；D：demo；N：讲稿。
- 讲稿会显示在同一投影画面上，不是私密演讲者视图，正式展示时请关闭。
- 点击 Start 8:00 排练，安排 8 分钟展示、2 分钟问答。以下是时间分配，不是逐字读完就一定达到的时长，务必连同点击一起排练。
- 三人分工：A 讲第 1–3 页；B 讲第 4–5 页；C 讲第 6–9 页。两人可在第 5 页之后交接。

## 90 秒 demo：边操作边讲

1. **0–15 秒：**第 4 页点击 Open pilot demo → Open example report。说：“这是纽约布鲁克林 3325 Neptune Avenue 的真实公开数据快照，不是实时验房结果。”
2. **15–35 秒：**展示概览，选择 Heat & hot water。说：“我们把记录整理成租客看得懂的问题，并提供看房时可以追问的事项。”
3. **35–60 秒：**点击 See evidence，展开记录。说：“每个问题可以回到证据查看。投诉不等于已确认违规，案件关闭也不代表维修完成。”
4. **60–80 秒：**展示看房清单，点击 Download viewing checklist。说：“最终可以带走一份实用的提问清单。年度虫害申报可能覆盖同一地块上的多栋楼，不能当作这间公寓的情况。”
5. **80–90 秒：**点击 Back to slides。说：“这个工具帮助租客提出更好的问题，而不是给房子出具安全保证。”

离线可看报告、查看内嵌证据、下载清单并运行内嵌模型。跳转外部来源页面需要网络，不建议在限时演示中依赖外部网页。

## 逐页中文讲稿

### 第 1 页：介绍｜0:00–0:25

我们展示的项目叫 Rental Radar。它帮助租客理解公开的楼宇记录，并在看房前准备更好的问题。今天会介绍一个可操作的试点、已经训练的模型、当前局限，以及下一步计划。

### 第 2 页：用户问题与范围｜0:25–1:05

用户从一个地址开始。我们把投诉、违规记录和年度虫害申报整理在一起，转化成租客可以采取行动的问题。有同学问过为什么只做纽约。我们的回答是：这是一个范围明确的试点，纽约的公开数据可以通过共同的地块标识关联。扩展到其他城市之前，还需要单独验证当地数据覆盖和匹配方式。

### 第 3 页：目前进度｜1:05–1:45

我们已经连接三个数据来源，生成可复现的报告，并训练了 XGBoost 和逻辑回归基线。准备好的数据包括 125 个地块、2,750 条按月观测。更严格的评估去除了跨数据分割边界重叠的 90 天标签窗口，并在 625 条留出记录上测试。用户可以查看报告和下载清单，但正式用户访谈与外部大模型评估还没有完成。

### 第 4 页：试点演示｜1:45–3:15

按照上面的 90 秒顺序操作。不必把按钮指令念给观众听，重点讲清：输入地址 → 理解问题 → 查看证据 → 带走看房问题。不要把保存的示例说成正在实时查询。

### 第 5 页：数据处理与可选大模型｜3:15–4:10

Python 负责获取、去重和统计数据，也负责准备历史模型特征。可选的大模型只用于解释限定范围内的证据，不负责上网搜索或计算总数。提示词要求引用证据，并禁止给出安全保证。我们检查输出结构和引用编号，但事实是否得到充分支持仍需要人工核对。目前 demo 的说明由规则生成，不依赖尚未测试的外部模型调用。真实的大模型用量和成本也还没有测量。

### 第 6 页：模型结果｜4:10–5:15

模型的预测目标很具体：未来 90 天内是否新增一条 Class C 违规记录。排除跨分割边界的标签窗口后，逻辑回归的排序表现和召回率更好；XGBoost 的精确率更高、Brier 评分更低。因此不能简单宣布某一个模型全面胜出。这些结果来自一小批有 HPD 历史的地块，不代表纽约全部出租房。问答时可以展示浏览器对真实留出样本运行保存的模型。

### 第 7 页：用户探索｜5:15–6:05

目前有一条回忆中的同学反馈：为什么只覆盖纽约？我们据此补充了试点范围说明，但不会把它当作已完成的访谈研究或经过核验的 Plause 记录。下一轮计划进行 5–8 次简短访谈，测试用户能否区分证据类型，以及清单是否改变他们看房时的问题。我们会同时记录希望增加和认为不需要的功能。

### 第 8 页：风险｜6:05–6:55

最大风险是过度解释数据。一个地块可能包含多栋建筑；投诉是报告，年度申报可能是业主自报，案件状态也不一定反映当前状况。因此我们区分证据类型、显示日期与来源，并使用中性的追问。模型还受到抽样偏差和校准不足的限制，不能直接作为公众安全评分。

### 第 9 页：下一步｜6:55–8:00

接下来会访谈租客、改进建筑身份匹配、扩大模型评估，并开展小规模试点。我们首先要确认“证据报告加看房清单”是否真正有用，再决定是否投入评分和城市扩展。当前优先级是实际帮助用户并避免误读，而不是提供一个普适的安全分数。最后留两分钟回答问题。

## 可选：实时查询其他地址

解压 `Rental_Radar_App.zip`，在包含 `demo_server.py` 的 `Rental_Radar_App` 文件夹打开终端。需要 Python 3.10 或以上，运行：

```text
python demo_server.py
```

打开 `http://127.0.0.1:8766`，进入 demo，选择 Look up another NYC address。填写街道门牌地址，不加公寓号，选择行政区和时间范围。需要网络，不需要大模型 API key。结束日期不包含在查询内，最长时间窗 731 天。精确地址匹配可能遗漏别名；没有查到记录不代表没有问题。若来源失败，回到明确标注的保存示例。

localhost 只属于运行服务的那台电脑，不是公开分享链接。队友可以打开各自收到的 HTML；需要实时查询时，分别运行本地服务。

## 可选：问答时展示模型实验

选择历史留出样本 → Run the trained model → 查看输入 → 展示 recorded outcome。这里是真实执行内嵌 XGBoost 树模型，不是动画假结果。但它不是对当前 demo 地址或新输入地址的实时风险预测，也不是经过全纽约校准的安全分数。

## 完成边界

已有验证记录：20 项单元测试通过；25 项离线输出／引用契约检查通过；625 条模型样本浏览器与 Python 的最大概率差约 2.49e-7。契约检查不等于真实大模型效果评估。外部 LLM 调用、实际用量成本和正式用户访谈仍待完成。目前成果在本地，尚未推送 GitHub 或创建 PR。
